# 录制模式说明

当前源码版本：v2.3.40 · 2026-10-03。

硬件金币通过 NFC 领取入口（`/client/nfc/<任务ID>?device=<设备ID>`）打开申请窗口，由玩家授权定位并在启用的门店范围内保存待领申请。商家扫描对应金币的固定设备码、核对玩家并收到实物金币后点击“确认领取”，正式奖励才进入玩家卡包；申请阶段不发奖励、不记金币。个人券二维码供玩家以后消费时核销；积分奖励在领取确认后入账，无需个人券核销。硬件任务不回答观察题，普通独立网页任务保留线索、观察题和范围校验。

本机录制另提供带演示标记的功能展示券：已通过的玩家可从卡包主动领取茶间集示例券，展示原始个人券二维码，商家核对后仅核销。它与正式寻宝奖励分开保存，不写正式claims、金币计数、积分、足迹、真实库存或常规统计；不要求实物NFC或定位，不能作为实体金币、门店范围或云端联动已验证的证据。入口由既有服务端录制变量控制，网页不新增模式开关；关闭后隐藏展示券并拒绝展示券接口，记录保留，正常注册、正式领奖和正常券核销继续使用。

更新已有项目须先备份实际持久数据库，再按顺序增量应用尚未执行的迁移；0014增加两张领取草稿表，0015增加商家资料草稿表，当前共28张应用表。录制展示券继续使用0010的两张隔离表，账号邮箱及验证使用0011，不用空库替换原数据。历史源码包保留各自版本；最终三端源码包按用户要求等待并行修改结束后统一生成，本轮未生成新包。正式手机公网定位、相机与网页内NFC读取需要HTTPS；NFC标签应写准确的领取网址。本批未部署云服务器或烧录设备；源码、软件测试、实际本机迁移和现场验收分别记录。旧版本章节保留历史记录，当前行为以本段及[技术架构](./技术架构.md)为准。


适用当前源码：v2.3.40 · 更新日期：2026-10-03。

录制模式在正常注册、密码登录与审核之外，临时提供“快捷演示登录”和独立“录制展示券”。它仍建立已通过的实际账号会话，方便录视频时切换演示角色。**网页没有录制开关**，启用与关闭都由服务端私有变量控制；保留源码是为了以后复用，不需要为了关闭功能删除代码。

## 启用条件与身份范围

服务端同时要求请求网址的主机为`localhost`或`127.0.0.1`，以及Worker变量`RECORDING_SHORTCUT_LOGIN`精确等于字符串`true`。默认关闭，`1`、未配置及`false`都不启用；公网网址即使设置变量也被拒绝。页面读取`recordingShortcutAllowed`决定是否显示按钮，`recordingLogin`每次请求仍重新校验，不满足返回403。

| 快捷入口 | 实际身份 | 限制 |
| --- | --- | --- |
| 寻宝者、探索者 | 当前未绑定浏览身份的专属已通过演示玩家；已有自己的演示身份可复用 | 两种玩家角色共用；不接管已有正式账号，不移动其卡包、草稿或其他记录 |
| 商家 | 绑定已有tea门店的专属已通过演示商家 | 只支持tea；不新建门店、地址、GPS、围栏、券或任务；不覆盖自行注册的同名商家 |
| 运营 | 通过显式首次初始化建立的`demo-admin` | 必须匹配真实初始化标记和已通过状态；不会接管自行注册的同名运营账号 |

商家和玩家演示账户使用随机密码摘要，不向前端返回密码。预设与录制身份的`request_id`为空，不进入真实注册申请列表或审核详情。GET读取页面状态不会自动创建录制账户，第一次明确快捷登录才建立相应身份。已登录商家/运营的关联浏览会话也不能执行玩家确认金币、领奖、投稿或草稿写入；这些操作仍要求player账号。

正常账号按“角色＋用户名”独立保存，寻宝者/探索者共用player账号，商家与运营分别注册并审批。录制模式不会恢复旧空验证码、共用访问码、站点拥有者请求头或历史手机号认证的写入权限。演示登录也不绕过正式NFC与网页任务的围栏、发布、作者限制、库存或一次领奖条件。独立展示券只走上节明确标记的演示分支，不能冒充正式领奖。

## 录制展示券的完整流程

卡包先显示正常奖励内容，“演示展示券”入口放在其后；服务端开关关闭后仍隐藏入口，录制券记录与正常奖励保持各自保存。

`recordingCouponAllowed`只是界面提示。已通过玩家在卡包明确点击才调用`recordingCouponGrant({requestId:UUID})`，固定属于茶间集（tea）。每玩家当前活动最多一张有效未用券，7天到期或用完后可领取下一张。券码为26个ASCII字符：`GTB-D-`加20位十六进制；个人二维码是原始券码，不跳网页。入口标“演示展示券”，卡包/弹窗/预览标“展示券”或“功能展示券”，流水标“展示核销”；演示身份始终明确，不可实际消费。

该功能独立保存于`recording_coupons`与`recording_coupon_requests`，不写正式claims、金币计数、积分/贡献/成就、足迹、真实库存或常规统计。它不要求NFC、GPS或围栏，因此能展示卡包与核销交互，不能作为实物金币与位置校验已通过的证据。正式NFC任务仍要求原有账号、已启用设备、范围/精度和库存条件。

领取前冻结UUID；网络结果不明确时保留原UUID，调用`recordingCouponStatus`只读核对本人精确结果，不自动重发。新UUID复用已有有效券也保存请求对应关系；券核销后，旧UUID继续返回旧券，不会混成下一张。商家按正常相机、图片或手工码预览，再明确确认一次核销，错店被拒绝；预览只读，重复核销不会第二次成功。展示券取消正式寻宝反馈和发现分享，避免演示记录进入正常业务。

两个展示券action、展示券预览/核销及展示数据读取都重新检查同一录制gate；关掉变量后隐藏展示券并拒绝这些接口，数据保留，正常券继续可用。快捷登录本身不发券，状态GET也不自动创建展示券。网页没有模式开关。

本机实际0008迁移已核对至22张应用表，已有一致性备份；迁移时18张原业务表完整数据摘要不变，撤销37份旧后台会话，保留17份玩家会话，历史认证标记新增0份，清理1条旧验证码挑战，完整性检查为ok、外键问题0。该结论对应迁移前后时点，不扩大为随后快捷登录创建演示身份也“完全零写”。本批没有执行云端迁移或更新。

## 录完视频后关闭

1. 在项目根目录私有配置中，将`RECORDING_SHORTCUT_LOGIN`改为`false`。若`.env`和`.dev.vars`都存在，两份均改为`false`，避免之后移除某份文件时恢复旧值；保留其他密码、地图和设备变量。
2. 停止当前开发服务，重新执行`npm run dev`，刷新页面。本地开发存在`.dev.vars`时，其Worker变量优先于`.env`，仅刷新浏览器不能替代服务重启。
3. 确认`GET /api/game`的`recordingShortcutAllowed`和`recordingCouponAllowed`均为`false`，三个登录入口不再显示“快捷演示登录”，玩家卡包和商家流水隐藏展示券。GET可能建立浏览会话，不把它当成无副作用健康检查。
4. 核对`recordingLogin`、`recordingCouponGrant`及`recordingCouponStatus`均返回403，旧展示券码的预览/核销也拒绝；不只验收按钮隐藏。再用常规用户名和密码登录，核对实际角色与绑定门店，并验证普通券仍可按正常条件预览/核销。

关闭开关不删除账号、卡包、草稿或审批数据，也不会自动注销已经建立的会话。需要退出当前身份时使用正常退出操作；不通过删数据库或密码摘要关闭录制功能。以后再次录制，仅在本机明确改为`true`并重启，原权限检查仍须通过。

## 与正常邮箱和图片功能的关系

三个登录入口均提供“邮箱登录”：输入已绑定邮箱，获取6位邮件验证码后登录，仍受实际账号角色、审核及封禁约束。寻宝者和探索者共用player账号，商家与运营各自绑定和登录；同一邮箱可在不同身份分别使用，不会打通权限。注册可选填邮箱，填写后必须验证；旧账号先用原账号密码加邮箱验证码绑定，绑定完成不会自动登录，也不会替换原密码。邮件服务未配置或发送失败时明确提示，账号密码登录继续可用。

邮箱登录/注册绑定、SMTP服务和门店示例/上传图片均是正常产品功能，不属于录制模块；关闭或移除录制时保留email-auth/smtp-mail、email-login-access、0011邮箱挑战、store-image及0012图片字段。MAIL_PASS是服务端私有发信密码，源码包不提供，不能用录制开关关闭邮箱。当前全迁移应用后25张应用表；0010阶段24表的历史描述保留其时点。

## 如需彻底移除

常规关闭只改变量并重启即可，记录保留。若以后明确要从源码彻底移除快捷登录与展示券，应先备份并核对下面的完整模块范围，再按顺序清理：

1. 先关闭服务端开关并重启，验证状态false、快捷API403及正常密码登录可用，再修改源码。
2. 删除`account-auth.ts`中的录制常量及三个录制函数，移除`accountAction`的`recordingLogin`分支；保留`ensureDemoAdmin`、正常注册、密码摘要、审核、登录和会话函数。
3. 移除`game-server.ts`录制相关import与状态字段、`game-types.ts`布尔字段，以及包装组件传参；保留`game-server.ts`的正常账号分发与`game-business.ts`的业务权限检查。
4. 删除`AccountAccess`的录制专用prop、状态、函数、按钮与局部样式；从根应用账号action白名单和登录后校验动作列表移除`recordingLogin`，保留普通`accountRegister`、`accountLogin`、`staffLogin`、`emailCodeSend`、`emailLogin`、`accountEmailBind`及Cookie核对。
5. 移除展示券grant/status实现及分发、两类录制布尔字段、Coupon.demo消费处、卡包领取入口和展示券modal分支，以及商家demo预览/核销路由与演示流水合并；保留正常couponPreview/redeem、扫描器、QR编码解码、卡包、未知结果处理与业务统计。
6. 清理公开示例与私有文件中的录制变量、仅针对录制的测试和说明；保留正常账号、权限和密码测试，重新运行对应检查并同步[技术架构](./技术架构.md)及运行说明。已有0010是迁移历史，不编辑已应用迁移，也不在源码清理时自动删演示表；归档/删除演示数据须另获明确授权，正常claims和账号绝不能连带删除。
