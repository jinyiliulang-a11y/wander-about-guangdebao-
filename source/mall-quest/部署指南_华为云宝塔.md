## 邮箱发信配置与验收

此工程沿用Workers+D1，由服务端TLS SMTP465发送6位验证码，没有启用附件中的Express/SQLite/Nodemailer进程。私有Worker变量配置`MAIL_HOST`（按发信账号区域选择SMTP主机）、`MAIL_PORT=465`、`MAIL_SECURE=true`、`MAIL_USER`、`MAIL_PASS`和可选`MAIL_FROM`（留空沿用账号）。阿里云DirectMail须使用已授权发信地址及对应SMTP密码，不能拿控制台登录密码代替。设置只保存在既有私有运行文件并重启服务；不要把实际密码加到公开.env.example、前端VITE变量或源码包。

0011应用后邮箱注册为可选，但填写就必须验证；同角色邮箱唯一，玩家/商家/运营分别绑定。旧账号邮箱默认为NULL，需原密码与邮箱验证码主动绑定。三个登录页提供邮箱入口，发信未配置明确503，不会退回网页显示验证码。部署后先在授权邮箱做一次发信测试，再核对实际收到、验证码消费、角色与审批；本机假SMTP测试不能证明服务器能够连接465或收件箱投递成功。发送网络结果未知保持原UUID，不能靠自动重试重复投递。

门店图片只使用验证后的单张Data URI存入D1（≤500 KiB、最长边1280），未接入OBS/R2。图片槽可替换/恢复3种示例，SQL版本校验防旧页面覆盖。运营与商家继续原门店权限，图片更新不改券奖励和有效期。

## 1. 先明确当前项目怎样运行

当前项目是 React 19 + TypeScript + Vinext/Vite + Cloudflare Worker/D1 工程，业务数据访问使用 `cloudflare:workers` 的 `DB` 绑定。虽然依赖中有 Next.js，它的当前启动方式并不是 `next start`。

现有 `npm start` 会启动 **Wrangler 本地 Worker 运行环境**，并把 D1 本地 SQLite 数据保存在项目的 `.wrangler/state`。本文采用这个已有运行入口，在 ECS 上用一个进程运行，通过宝塔 Nginx 提供 HTTPS，适合比赛演示、小范围试用。

**这不是 Cloudflare 托管生产运行环境，也不是已经实现的生产级自托管服务。** 持久化、备份和进程管理可以让演示更可靠，但长期正式运营应另行选择 Cloudflare 托管 Workers/D1，或者完成自托管服务与数据库适配、密码恢复、真实身份验证和生产鉴权运维，再部署到 ECS。不能直接把 D1 换成宝塔 MySQL，也不能只上传 `dist/client` 作为静态网站，否则登录、发布、领奖、核销和硬件同步会失效。

当前 `.openai/hosting.json` 的 R2 配置为 `null`；线索照片使用 Data URL 存入 D1，没有已接入的 R2 或华为云 OBS 上传服务。本次部署不需要购买 MySQL、Redis 或 OBS。

访问关系：

```text
手机浏览器 / NFC 打开的任务网址 / 金币设备
        ↓ HTTPS 443
华为云 ECS 安全组 → 宝塔 Nginx（证书、反向代理）
        ↓ http://127.0.0.1:8787
单个 Wrangler 本地 Worker 进程（PM2 管理）
        ↓ DB 绑定
项目 .wrangler/state 内的持久化 SQLite
```

## 4. 华为云安全组、域名与宝塔软件

1. 在华为云 ECS 控制台确认已绑定公网 IP。给域名添加 A 记录，记录值为该公网 IP。
2. 入方向安全组放行 TCP `80`、`443`，来源可以为 `0.0.0.0/0`；使用 IPv6 时另配置实际 IPv6 规则。
3. SSH 实际端口、宝塔面板当前端口，仅向你自己的管理 IP 放行。面板端口以面板设置为准，不假定一定是 8888。
4. **不要向公网开放 8787、5173、9229、9230 或 SQLite 文件。** 宝塔防火墙与华为云安全组均按同样原则配置。
5. ECS出方向允许安装依赖和业务需要的DNS、HTTPS。金币另外需要一张可以上网的Wi-Fi网络；设备所在网络需允许DNS、HTTPS及时间同步UDP123，这不是要求在ECS安全组开放入方向UDP123。
6. 宝塔软件商店安装 Nginx、Node.js 版本管理器；选择 Node 24 LTS 的受支持补丁版本。PM2 后面用该版本的 npm 安装。服务器已装宝塔 8.0.5 就无需再次运行宝塔安装脚本。
7. 重新打开宝塔终端，检查 `node -v`、`npm -v`。如果找不到 Node，记录版本管理器显示的实际安装目录，后续配置 PATH。

## 5. 上传源码，准备单独运行账号

上传交付的源码 ZIP 到服务器并解压，将 **包含 `package.json` 的项目目录内容** 放到 `/www/wwwroot/guangdaobao`。不要把外层 `outputs/` 当作项目根目录。

Windows 的 `node_modules`、本机 `dist` 不要上传；应在 Linux 重新安装、构建。普通源码包也不包含你电脑上的真实数据库、玩家记录、设备 Token 或后台密码。

下面系统准备命令在宝塔 root 终端执行；已有同名账号时不会重复创建：

```bash
apt-get install -y curl ca-certificates unzip libc++1 openssl
id mallquest >/dev/null 2>&1 || useradd --create-home --shell /bin/bash mallquest

chown -R mallquest:mallquest /www/wwwroot/guangdaobao
```

后面的安装、构建、PM2 命令使用 `mallquest` 账号。`sudo -iu` 后，重新设置当前终端变量：


`v24.xx.x` 同样是占位值；不要原样保留。如果服务器已有全局 Node 24，可以省略 `NODE_DIR` 和 `PATH` 两行。未来重开终端时也要确保使用相同 Node 版本。

```bash
cd "$APP_DIR"

npm run check
./node_modules/.bin/workerd --version
```

保留锁文件，不使用 `npm install --force`；当前项目运行和构建需要开发依赖、可选依赖，不能只安装 `--omit=dev`。若 workerd 出现 GLIBC、CPU 架构或缺少动态库错误，先检查服务器系统与 Linux 依赖，不用 Windows 的依赖目录补上。

## 7. 配置后台私有变量并构建

当前玩家、商家与运营使用独立用户名和密码。商家与运营注册先待审核，管理员在`/staff/accounts`核对并通过申请；商家登录后绑定审核创建的门店，不可选择任意旧门店获得管理权限。旧模拟验证码、localhost空码、共用`DEMO_STAFF_CODE`及站点拥有者请求头免密已关闭。

账号按“角色＋用户名”唯一：寻宝者/探索者共用玩家账号；商家和运营分别注册，即使同名也有各自密码与权限。运营角色的`admin`是预设保留用户名，其他运营普通注册使用自己的用户名；玩家或商家同名不获得运营权限。首次管理员初始化遇到已有同名运营账号（包括待审或退回）不会覆盖该账号或自动批准，配置变量不能当作审批或密码重置接口。预设和录制账号不进入真实申请审核列表。

管理员首次初始化使用服务端`DEMO_ADMIN_PASSWORD`，只在数据库没有角色为admin、用户名为admin的账号时建立账号，保存随机盐PBKDF2摘要，改变变量不会覆盖已有密码或审批状态。用户最终授权现在初始化本机账号，录制管理员为`admin`/`${DEMO_ADMIN_PASSWORD}`，实际启用结果见技术架构；公网部署者自行选择首次密码，不复制本机录制配置。联系电话只是填写的联系资料，没有短信/实名验证，密码恢复与完整生产风控尚未实现。

“快捷演示登录”是录视频期间保留的额外入口，不是公网登录方式。服务端同时检查页面主机为`localhost`或`127.0.0.1`且`RECORDING_SHORTCUT_LOGIN`精确为`true`，每次请求重新校验，不满足返回403。运营仅进入初始化的演示管理员，商家仅绑定已有tea，玩家两种角色共用专属演示账号，不接管正式账号、不新建门店/坐标/券/任务。部署环境保持`RECORDING_SHORTCUT_LOGIN=false`；录完本机视频也改为`false`并重启，按钮及接口一起停用，密码登录与审核保留。

只在不存在私有配置时创建初始化变量，避免覆盖已有地图和设备设置；下面随机密码不打印到终端、不写入命令历史，使用服务器私有编辑器查看并妥善保存：

```bash
cd "$APP_DIR"
umask 077
if test -f /etc/mall-quest/runtime.env; then
  printf '%s\n' '已有私有配置，保持不变；在私有编辑器补充缺少的初始化变量。'
else
  ACCOUNT_INIT_PASSWORD="$(openssl rand -hex 32)"
  if [[ "$ACCOUNT_INIT_PASSWORD" =~ ^[0-9a-f]{64}$ ]]; then
    printf 'DEMO_ADMIN_PASSWORD="%s"\nRECORDING_SHORTCUT_LOGIN=false\n' "$ACCOUNT_INIT_PASSWORD" > /etc/mall-quest/runtime.env
    chmod 600 /etc/mall-quest/runtime.env
  else
    printf '%s\n' '初始化密码生成失败，未创建配置；停止部署并检查openssl。'
  fi
  unset ACCOUNT_INIT_PASSWORD
fi
test -s /etc/mall-quest/runtime.env
```

既有服务器升级时，先增量应用0008，再在同一份私有变量文件补充`DEMO_ADMIN_PASSWORD`并重启服务；不存在上述同名运营账号时，第一次账号请求会完成初始化。已有admin时请用数据库中该账号的实际密码，新变量不是重置或批准待审申请的方式。没有已授权管理员且未完成初始化时，不会通过普通运营注册自动授予后台权限。`LOCAL_STAFF_DEMO`、`DEMO_STAFF_CODE`和`SITE_OWNER_ID`旧变量不再授予账号登录权限，可清除旧授权配置；不要依赖反代Host或客户端请求头免密。

在服务器私有编辑器中向同一份`/etc/mall-quest/runtime.env`补充`AMAP_WEB_KEY`和`AMAP_SECURITY_JS_CODE`，并确认`RECORDING_SHORTCUT_LOGIN=false`，保留已有初始化密码和其他配置，文件权限继续0600。值来自高德控制台的Web端JS API应用；不要复制开发电脑的`.dev.vars`，不要将真实安全密钥写入源码、网页、`VITE_*`或`NEXT_PUBLIC_*`变量。原有`--env-file`启动参数继续使用，配置修改后重启服务并检查是否加载。高德控制台配置最终HTTPS域名白名单；服务器需允许向`webapi.amap.com`和`restapi.amap.com`出站HTTPS，浏览器需能加载高德SDK。

构建：

```bash
cd "$APP_DIR"
npm run build
test -f dist/server/wrangler.json
test -d dist/client
```

本文在启动时显式传入 `/etc/mall-quest/runtime.env`，构建不覆盖这份私有配置。不要同时保留根目录/构建目录中的 `.dev.vars` 作为另一份变量来源，也不要只创建根目录 `.env` 或只把值设为PM2普通环境变量，就以为已经配置Worker绑定。当前Wrangler的显式env-file行为以最终部署启动验收为准。

## 9. 宝塔创建站点、反向代理与 HTTPS

1. 宝塔「网站 → 添加站点」，域名填你的真实域名，路径设 `/www/wwwroot/guangdaobao-site`，数据库选“不创建”，PHP 选“纯静态”。这个空目录只用于站点和证书验证，不作为源码公开目录。
2. 网站设置「SSL → Let's Encrypt」申请证书。域名解析正确、80 可达、备案状态允许访问后再申请；失败时可在宝塔上传已申请的公信证书和完整链。
3. 证书成功后开启强制 HTTPS。HTTP 80 保留证书验证/跳转作用，对外业务使用 HTTPS 443。
4. 网站设置「反向代理」添加代理，目标 URL 为 `http://127.0.0.1:8787`，发送域名选择你的真实域名。
5. 修改**这个站点**的反向代理配置，关闭代理缓存。不要整体覆盖宝塔 Nginx 主配置或其他站点，不破坏 `.well-known/acme-challenge` 的证书续期配置。

在 HTTPS 站点中使用下面的代理块，替换宝塔刚生成的同一个 `location /`，不要再叠加第二个 `location /`：

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # ECS没有可信Sites身份网关，移除客户端提供的身份头。
    proxy_set_header oai-authenticated-user-id "";
    proxy_set_header oai-authenticated-user-email "";
    proxy_set_header oai-authenticated-user-full-name "";
    proxy_set_header oai-authenticated-user-full-name-encoding "";

    # 程序最多接收约1.2MB JSON；五张线索照片合计最多1MiB。
    client_max_body_size 2m;
    proxy_connect_timeout 10s;
    proxy_read_timeout 60s;
    proxy_send_timeout 60s;
    proxy_buffering off;
    proxy_cache off;

    # 内部HTTP不会自动赋予Secure；在HTTPS代理处补全会话Cookie属性。
    proxy_cookie_flags mall_player secure httponly samesite=lax;
    proxy_cookie_flags mall_staff secure httponly samesite=lax;
}
```

同时为该站点添加私有文件保护（放在 `server {}` 中，与代理块平级）：

```nginx
location ~* /(?:\.env(?:\.[^/]*)?|\.dev\.vars(?:\.[^/]*)?|\.wrangler|\.sites-runtime|\.git)(?:/|$) {
    return 404;
}
```

空网站根目录加反向代理已避免直接提供源文件，上面保护进一步避免误放私有文件。源码、备份和数据库不能放在站点公开根目录。

`X-Forwarded-Proto`只是转发信息；当前程序根据`Request.url`判断Cookie Secure及生成动态入口，不能假设这一头会自动修正内部URL。启动命令的`--local-upstream "$DOMAIN" --upstream-protocol https`配置正确公开origin，这里的`proxy_cookie_flags`进一步补全Cookie属性；后面仍需实际验收浏览器Cookie和动态入口HTTPS。若Nginx报此指令不认识，在宝塔软件商店升级Nginx到支持版本，不直接删去属性后当作完成。该站点不要保留冲突的PHP处理、静态扩展名location或`try_files ... /index.html`：页面、`/_next`资源与`/api`均交给同一个Worker。

保存前在宝塔检查配置，或用 root 终端执行：

```bash
/www/server/nginx/sbin/nginx -t
```

检查通过后在宝塔重载 Nginx。不开放 8787 端口。不对整个站点加 Basic Auth：硬件 `/api/hardware/sync` 使用 Bearer Token，Basic Auth 会占用同一个 Authorization 头。后台保护使用项目自己的独立账号与密码会话。

## 10. 浏览器验收：先公网，再硬件

基础检查：

```bash
curl -I https://treasure.example.com/
```

| 导出 | 商家/运营Excel和CSV正常下载，内容与当前筛选范围一致 |
| 重启 | 完成开机服务后重启ECS，站点恢复，已有数据仍在；首次部署可先手动重启进程验证 |

普通匿名Cookie可以读取公开API资料，客户端页面仍需玩家账号登录；清Cookie不授予核心业务权限，历史手机号认证标记也不替代当前密码登录。账号未接短信/实名验证，不能当作完整生产防刷方案。以上是部署后的实际验收清单，不代表已经替你在ECS完成。

## 11. 金币硬件与 NFC 的云端参数

网站上云后，金币无需继续连接某一部固定手机的热点。它仍必须连接能访问公网的 **2.4 GHz Wi-Fi**：可换成商场/现场路由器的 2.4 GHz 网络，或继续使用手机 2.4 GHz 热点。Wi-Fi名称、密码和 Backend 地址改变时要配网；单纯网页 UI 小改通常无需重新烧录。

设备网络需要 DNS、HTTPS出网和时间同步。当前源码使用证书 bundle 验证 HTTPS，并通过 `pool.ntp.org` 同步时钟；设备网络要允许对应 DNS与UDP123，否则可能因为系统时间或证书校验无法连接。

### 配网页面填写

| 字段 | 内容 |
| --- | --- |
| SSID / 密码 | 现场可联网的2.4GHz Wi-Fi信息，只在设备配网页面填写 |
| Backend URL | `https://treasure.example.com`，**最终真实域名根地址** |
| Device ID | `coin-tea-01`，需与云端登记一致 |
| Device Token | 与云端登记一致的私有Token，不是账号密码 |

硬件公网配置必须使用 `https://` 且是域名，不能填写公网 `http://IP`；`http` 私网IPv4是本地调试兼容入口。当前 HTTP 客户端不自动跟随重定向，所以 Backend 不要填 `http://` 期待跳到 HTTPS，也不要填写会被转跳到另一个域名的 `www` 地址。

### 新服务器上的设备登记

如果已经私有迁移数据库和匹配的设备配置文件，先保留 Token；使用已有设备 ID、门店 ID 与配置，不加 `--rotate`。

如果服务器是新数据库，需要先执行数据库迁移，并实际请求一次`GET /api/game`，让演示门店生成。只打开首页不作为已经完成种子初始化的证明。下面第一条curl只用于首次初始化验收，会创建一个匿名演示玩家；日常健康检查改用首页。随后配置操作会写设备登记并把茶饮店切到硬件模式；仅对你确实要接入的设备执行：

```bash
cd "$APP_DIR"
curl --fail --silent --show-error "https://$DOMAIN/api/game" --output /dev/null
npm run hardware:configure -- --device=coin-tea-01 --store=tea --server="https://$DOMAIN" --activate
chmod 600 .sites-runtime/hardware-coin-tea-01.json
```

这会把私有配置保存到 `.sites-runtime/hardware-coin-tea-01.json`，不会把 Token 打印出来。用服务器私有编辑器查看并填入设备配网页面，不要将文件分享到公开群或打进源码 ZIP。如果服务器没有原来的私有配置文件，此命令会生成新 Token，需要给设备填新值；不要假定只换网址就能匹配旧凭据。`--rotate` 会主动轮换凭据，平时不要加。

**新库还需要完成任务绑定。** `--activate`仅登记、启用设备并设置门店模式，没有设置`bound_task_id`。用商家账号登录，进入“设备与金币”管理页，在`coin-tea-01`卡片的“绑定任务”中选择已发布的茶饮任务（ID为`quest-tea`）并保存绑定。若已有数据迁移，检查其绑定仍正确。未绑定时动态入口返回409；有设备登记不等于能取动态QR。店铺、任务、券模板还要保持启用、有效且有库存。

设备同步请求如下，仅展示协议，不填写真实Token：

```http
POST /api/hardware/sync HTTP/1.1
Host: treasure.example.com
Authorization: Bearer <设备私有Token>
Content-Type: application/json

{"deviceId":"coin-tea-01"}
```

正常响应是裸JSON的五个字段：

```json
{
  "storeId": "tea",
  "storeName": "茶间集",
  "taskId": "quest-tea",
  "available": true,
  "claimCount": 3
}
```

这是**响应形状示例，不是实时库存或已测结果**。它只读认证、任务可用状态和本店领取总数，不会创建玩家、不发券、不核销。`available=false`也可能是正常200响应；401核对Token/设备启用，403等异常按实际返回排查，503检查数据库/服务，GET得到405属正确方法限制。当前固件不请求旧的 `/code`、`/status` 验证码流程。

### NFC 标签与二维码

1. 在商家信息页复制本店实际已发布任务入口，比如 `https://treasure.example.com/client/nfc/quest-tea`。
2. 用安卓 NFC Tools 将该 URL 写入设备背面 NTAG213 标签。不要写设备Token、后台密码、`192.168.4.1`配网页地址或旧局域网IP。
3. NFC打开专门领取入口；玩家明确点击授权定位，通过门店范围、账号、设备与库存校验后直接领券并记录金币，不再答观察题。手机卡包的个人券二维码供商家仅核销；被动标签网址可以转发，不能称为可信物理签到。
4. NFC被动标签不受固件控制，Backend改变不会自动重写标签，需要手机再写一次。2026-10-02已授权安装带云端地址适配的维护固件（记录摘要289507bf…）；本次只更新网页与增量数据库，不烧录设备。金币屏幕历史入口二维码与手机个人券二维码用途不同，当前领券使用NFC专用入口、核销使用玩家卡包码。设备显示有效入口及完整现场联动仍须另测。
5. 原设备中文线索是本地固件内容。网页发布/修改线索不能被当作设备已经自动下载新线索；当前sync仅有上述五字段。若要任意商家新线索自动下发，还需扩展协议与固件。

动态QR候选在相同根域名使用`GET /api/hardware/entry?deviceId=coin-tea-01`，沿用设备Bearer，没有新增环境密钥或数据库迁移。响应为六字段`deviceId/storeId/taskId/entryUrl/expiresAt/ttlSeconds`，票名义有效期120秒；新票不会立即撤销仍在期限内的旧票，停用、解绑或轮换凭据会使旧票失效。`entryUrl`最多160个ASCII字节，建议使用较短的真实域名；默认设备与任务ID、HTTPS默认端口及当前到期编码下，主机名可用预算约35个ASCII字符，以实际完整响应长度为准。超长应按接口错误处理，不能截断网址。代理覆盖整个`/api`且不缓存，也不要重写或去掉手机任务网址的`entry`查询参数。票过期后手机重扫；它与玩家领到的个人券QR用途不同。保留的静态NFC兼容入口意味着动态票不构成全平台强制到店证明。

完成登记、绑定与公网反代后，可在`mallquest`终端做一次不打印Token或完整入口票的接口检查。该命令只请求动态入口，不领券、不核销；它证明服务器接口，不代替设备实测：

```bash
cd "$APP_DIR"
node --input-type=module <<'NODE'
import { readFileSync } from 'node:fs';
const cfg = JSON.parse(readFileSync('.sites-runtime/hardware-coin-tea-01.json', 'utf8'));
const base = new URL(cfg.serverUrl);
if (base.protocol !== 'https:') throw new Error('请先配置最终HTTPS服务器地址');
const endpoint = new URL('/api/hardware/entry', base);
endpoint.searchParams.set('deviceId', cfg.deviceId);
const res = await fetch(endpoint, {
  headers: { Authorization: `Bearer ${cfg.token}` },
  redirect: 'error', signal: AbortSignal.timeout(15000),
});
if (!res.ok) throw new Error(`动态入口HTTP ${res.status}，检查绑定、库存、授权和日志`);
const data = await res.json();
const entry = new URL(data.entryUrl);
const fields = Object.keys(data).sort().join(',');
if (fields !== 'deviceId,entryUrl,expiresAt,storeId,taskId,ttlSeconds'
    || data.deviceId !== cfg.deviceId || data.storeId !== cfg.storeId
    || entry.origin !== base.origin || entry.protocol !== 'https:'
    || !/^[\x00-\x7f]+$/.test(data.entryUrl)
    || Buffer.byteLength(data.entryUrl, 'utf8') > 160
    || !(data.ttlSeconds > 0 && data.ttlSeconds <= 120)
    || !(data.expiresAt > Date.now())) {
  throw new Error('动态入口字段、公开HTTPS origin、长度或有效期不符合要求');
}
console.log({ http: res.status, origin: entry.origin, path: entry.pathname,
  urlBytes: Buffer.byteLength(data.entryUrl, 'utf8'), ttlSeconds: data.ttlSeconds });
NODE
```

硬件实物验收顺序：能联网 → OK同步 → 中文线索和上下翻页 → 手机碰NFC打开专用领取入口 → 登录玩家账号并明确授权新定位 → 圈内直接领券、圈外拒绝 → 设备观察claimCount增长并提示/短音 → 同请求与同店重复领取不重复记金币 → 商家扫描手机卡包个人券、核对条件后仅核销 → 断网/恢复与重启重建基线。没有观察题或商家确认发券步骤。保留历史动态入口的设备另测验票刷新与到期隐藏；个人券码为原始券码而非网页网址。第一次同步只建立静默基线，不因为旧券总数就播放领奖音效；核销不是新增领取，不应触发新的挖宝音效。

### 备份

本地D1是文件状态。对一致性有要求的备份先停同一PM2进程，复制**完整状态目录**。下面在 `mallquest` 账号执行，备份目录不在网站公开目录：

```bash
export APP_DIR=/www/wwwroot/guangdaobao
export BACKUP_DIR=/home/mallquest/backups

  if tar -czf "$BACKUP_FILE" -C "$APP_DIR" .wrangler/state .sites-runtime -C /etc/mall-quest runtime.env \
     && tar -tzf "$BACKUP_FILE" >/dev/null; then
    BACKUP_OK=1
    chmod 600 "$BACKUP_FILE"
  fi
  if pm2 start guangdaobao; then
    printf '%s\n' '应用已重新启动，请再检查首页和PM2状态。'
  else

  fi
  if test "$BACKUP_OK" -eq 1; then
    printf '%s\n' '备份已完成并通过归档读取检查。'
  else

```

不要用 `cat` 输出备份中的私有配置。备份成功后再以私有加密方式保存一份到其他位置；不能只靠同一块云盘上的备份。建议每天备份并保留若干天，设置宝塔计划任务时也要先验证这套停止/备份/恢复流程，不能备份失败后一直让网站停着。

### 更新网站

1. 先做上面的状态备份，另保存当前已验证的源代码/构建包版本。
2. 上传新代码到单独目录检查完整性，不直接把整个项目目录覆盖成新压缩包。
3. 更新源代码时排除 `.wrangler/`、`.sites-runtime/`、`.dev.vars`、`node_modules/` 等状态与私有配置；保持项目目录、`/etc/mall-quest/runtime.env`和进程名称不变。
4. 锁文件改变时重新 `npm run install:ci`，然后 `npm run check`、`npm run build`。生成新构建时应有维护窗口；需要无中断更新则另行设计发布目录和共享状态方案。
5. 有数据库迁移时，先阅读迁移SQL并停止服务，在已备份的数据上应用仓库迁移；没有数据库变更时不重复初始化。应用迁移可使用当前 `npm run db:local`，其记录已应用迁移，不是清库。不要执行 `db:generate` 来猜线上迁移。
6. 再执行：

```bash
cd "$APP_DIR"
pm2 restart guangdaobao
pm2 save
curl -I https://treasure.example.com/
```

7. 验收登录、深层任务入口、已有券、商家核销、硬件只读sync/动态entry以及手机布局。Node主版本或系统升级后，PM2开机服务里的路径也需更新。域名变化时还必须更新PM2保存的local-upstream启动参数、宝塔域名/证书、设备Backend和NFC网址；单独`pm2 restart`不会把另一终端新设的DOMAIN替换进已保存参数。

### 回滚

没有数据库迁移的UI更新：恢复上一版已验证的代码/构建，保持当前数据状态和`/etc/mall-quest/runtime.env`不变后重启。

存在数据库迁移：不要直接用旧代码读取已变更的数据。先停服务、保存失败版本当前状态，再恢复**成套的对应代码和备份状态**到相同路径并重启；恢复备份会回退备份后的领取、核销等记录，需明确记录这段数据影响。不要为“修复502”删除 `.wrangler/state` 或重新生成全新数据库。

## 13. 常见故障定位

| 现象 | 先检查 |
| --- | --- |
| 宝塔502 | `pm2 status`、应用日志、8787是否在本机监听；前台进程是否已退出或与PM2抢端口 |
| 首页可打开但任务刷新404 | 是否把dist/client当静态站点；整个`location /`必须反代Worker |
| API503 / no such table | DB绑定、迁移是否执行；启动与初始化的工作目录及persist-to是否一致 |
| 后台密码无效 | 确认0008迁移、账号申请是否通过、用户名/密码/入口身份是否匹配；admin是否曾初始化。`DEMO_ADMIN_PASSWORD`只初始化，不重置已有密码；检查PM2显式env-file及运行账号读取权限 |
| 后台空密码也能登录 | 常规入口必须校验实际账号密码，不接受旧LOCAL_STAFF_DEMO或共用访问码；本机“快捷演示登录”另有显式录制开关，录完设false并重启，公网不得开启 |
| 重启后券全没了 | 是否删了.wrangler/state、切换工作目录、修改persist-to或启动了第二套空数据库 |
| 手机相机不能开启 | 用真实HTTPS域名，允许浏览器相机权限；不要用公网HTTP或自签证书 |
| 上传413 | 检查Nginx的2m限制与程序照片1MiB限制；不靠无限放宽body绕过程序限制 |
| 金币Network failed | 2.4GHz与出网、Backend最终HTTPS域名、DNS、证书链、SNTP时钟、服务器日志；不能只以手机首页可达当作设备接口通过 |
| 金币401 | 私有Token是否与当前数据库token_hash对应、设备是否enabled，是否错误填写账号密码 |
| 动态入口409 | 检查设备是否绑定已发布任务、有效模板及剩余库存；仅hardware:configure --activate没有绑定任务 |
| 动态入口为HTTP或域名错误 | 检查PM2保存的local-upstream及upstream-protocol=https；仅X-Forwarded-Proto不足；entryUrl需与设备Backend同origin |
| 金币200但没有领奖提示 | 第一次静默基线正常；检查claimCount是否增长，available=false是否任务下架/库存用尽，商家核销不增加claimCount |
| NFC还开旧IP | 标签URL需用手机重新写；改网页或设备Backend不会改被动标签内容 |
| 内存不足/构建被杀 | 看free与进程内存，升级内存或同架构Linux构建；不要删锁文件/数据库解决OOM |

部署完成的标准是：**有效HTTPS公网域名 + 单进程Worker + 持久状态与可恢复备份 + 登录/领奖/核销实际验收 + 金币在真实网络成功sync和反馈**。

历史部署指南核对了Wrangler命令参数和绑定加载流程，独立测试目录的数据库迁移与17张业务表检查通过。本机Windows沙箱阻止了该历史隔离测试的已构建入口esbuild目录访问，因此当时的HTTP、登录和外部env-file实际注入未运行。v2.3.31软件与本机20表迁移证据保留为历史，本版v2.3.32账号迁移和软件验收见技术架构；这些结果仍不等于Linux服务器部署成功。你的ECS、证书、公网访问和实物联动须在部署环境验收，不能把文档或构建通过当作部署完成。

## 电子围栏、门店活动与附近浏览验收（沿用v2.3.31，账号按v2.3.32）
